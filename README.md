This project use in softMC product which is for Hexagon Vision CMM Machine

## Master_Duo

Axis/drive order: 1=X, 2=Y, 3=Z, 4=X_F, 5=Z_F. `gXYZ` remains a three-axis group; the host continues to move X/Y/Z. X_F follows X.PCMD and Z_F follows Z.PCMD at GearRatio=1.

- `CONFIG.PRG`: `sys_simulated=1` bypasses hardware bus setup and uses five simulated axes; set it to `0` for five physical CDHD drives.
- Physical startup runs the five-drive `EC_SETUP.PRG`, then `AX_SETUP.PRG` and `ROBOT.PRG`. AX_SETUP retains the original X/Y/Z routines and adds Setup_Axis_4/5 to copy X/Z base settings and motion modes into X_F/Z_F. `PARA.PRG` retains the original master-axis values and adds SetXFParameters/SetZFParameters to copy only its ten X/Z overrides. `DUOSET.PRG` only binds electronic gearing; it does not set axis parameters. Simulation runs SIMSETUP then AX_SETUP's follower routines (skipping physical master setup), followed by PARA and DUOSET.
- Startup binds only when X/X_F and Z/Z_F feedback positions agree within their master's `PESettle` (currently 0.0028). Otherwise it waits for the host's homing command. It does not move or automatically home on power-up. `sys.NoMotion=1` is retained from the original CONFIG; motion authorization remains the existing host/site procedure.
- Host group homing runs five drive-internal homes, with gearing disconnected: Z/Z_F, then X/X_F, then Y. Drive 4 copies X's method/offset; drive 5 copies Z's. DS402 status word 0x6041 bits 10/12/13 determine completion/error. After disabling/restoring CSP and checking positions, the pairs are rebound and enabled. Failures leave the axes disabled and unbound.
- Normal group/master enable includes followers. Master disable disables its follower; follower disable/error is linked back to the master. Do not independently Move/Jog/Stop X_F or Z_F: Stop/Jog of a slave can remove gearing. Rehome before restoring a disconnected pair.
- Keep the host `grEn(socket,seq,group,enable)` interface: it delegates to grEnable and enables/disables all five axes. Enable=1 starts X_F/Z_F before gXYZ; Enable=0 disables gXYZ and both followers. Use this interface rather than a direct gXYZ.En assignment.
- Mode changes wait for homing cleanup and all five axes to stop. Reset requests homing cancellation before clearing faults or restarting tasks; homing checks cancellation before each pair starts, while polling, and before rebinding/enabling.

`DUOTEST.PRG` is an explicitly started, simulation-only regression test; AUTOEXEC never runs it. It checks individual/group movement, 1:1 command positions, disable/re-enable, invalid enable values, rejection of mismatched positions both when binding and when re-enabling an already-bound pair, simulated homing/rebinding after an existing group attachment, and cancellation/recovery. Read `duoTestPassed` and `duoTestError` after it finishes. The test temporarily authorizes simulated motion and restores `sys.NoMotion` afterwards. Expected negative tests can leave error history 20801/20802/20615 even when `duoTestError=0`.

Verified on 90.0.0.1, firmware `MULTIBUS 0.4.21.2r20-C2`, with no EtherCAT slaves: the simulation test including legacy grEn five-axis enable/disable passed all 18 assertions (`duoTestPassed=18`, `duoTestError=0`). Final clean startup retains the Hexagon simulation project, with `sys_simulated=1`, `sys.NoMotion=1` and all five axes disabled. Simulation homing only resets simulated user coordinates; it does not test the real drive homing procedure.

No-slave simulation cannot verify real PDO/SDO responses, home switch wiring, servo polarity, mechanical squareness, or safe dual-drive homing. Before physical operation, verify each follower's wiring/home switch and absolute mechanical alignment independently; identical numerical coordinates are not proof of mechanical alignment. Pair En requests are sequential controller commands, not a hard-synchronized drive-start guarantee.

Hardware commissioning: connect the five drives in the order above, verify independent homing and limits with the mechanism safe, set `sys_simulated=0` in CONFIG and reinitialize. Retain `sys.NoMotion=1` until the site's motion authorization procedure is completed. EC_SETUP/AX_SETUP are manually extended for Master_Duo; regeneration by the three-axis Configurator must preserve the five-axis additions. The original X/Y/Z settings and PARA values remain unchanged. Official gear safety semantics: [SlaveDisable](http://softmc.servotronix.com/wiki/MC-Basic:axis.SLAVEDISABLE), [SlaveDisconnect](http://softmc.servotronix.com/wiki/MC-Basic:axis.SLAVEDISCONNECT), [Gantry Issues](http://softmc.servotronix.com/wiki/Gantry_Issues).
